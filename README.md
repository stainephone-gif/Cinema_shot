# Cinema_shot — раскадровка видео по ключевым кадрам

`cinema_shot.py` берёт короткое видео и сохраняет в отдельную папку JPG-кадры только
в тех местах, где что-то меняется:

| Событие | Что сохраняется |
|---|---|
| Склейка (монтажный стык) | последний кадр **до** склейки и первый кадр **после** |
| Смена крупности внутри плана (деталь / крупный / средний / общий) | первый кадр новой крупности |
| Изменение состава героев: люди и животные (массовка на фоне не считается) | первый кадр с новым составом |
| Начало и конец видео | первый и последний кадры |
| Опционально: кадр раз в N секунд внутри плана | флаг `--interval` |

Рядом с кадрами кладутся `manifest.csv` и `manifest.json` (кадр, таймкод, номер плана,
состав героев вроде «1 человек, 1 собака», число всех фигур в кадре, крупность, причина), а с флагом `--contact-sheet` — общая картинка
`contact_sheet.jpg` из миниатюр.

## Установка

```bash
python -m pip install -r requirements.txt
```

На Windows команда `pip` сама по себе часто не находится (не добавлена в PATH), поэтому
вызывайте её через `python -m pip`. Если и это даёт «No module named pip», один раз
выполните `python -m ensurepip --upgrade`.

Нужен Python 3.9+ и OpenCV не ниже 4.5.4 (проверено на 5.0). ffmpeg не требуется.

Используются две модели из [opencv_zoo](https://github.com/opencv/opencv_zoo), обе кладутся в `models/`:

* `face_detection_yunet_2023mar.onnx` — лица (YuNet, ~230 КБ, лежит в репозитории);
* `object_detection_yolox_2022nov.onnx` — люди (YOLOX-S, ~35 МБ, скачивается автоматически
  при первом запуске; без сети программа продолжит работать только по лицам).

## Использование

```bash
python cinema_shot.py clip.mp4
python cinema_shot.py "D:\Видео\clip.mp4" --contact-sheet     # Windows: путь с пробелами и кириллицей — в кавычках
```

Кадры появятся в папке `clip_storyboard` рядом с видео.

Чтобы обработать все видео из папки подряд, укажите папку вместо файла:

```bash
python cinema_shot.py "D:\Видео"                                # результаты рядом с каждым видео
python cinema_shot.py "D:\Видео" -o "D:\Раскадровки" --contact-sheet   # все результаты в одну папку
python cinema_shot.py "D:\Видео" -r                             # включая вложенные папки
python cinema_shot.py a.mp4 b.mov "D:\Ещё видео"                # можно смешивать файлы и папки
```

Файлы берутся по алфавиту, для каждого создаётся своя папка `<имя видео>_storyboard`.
Модели загружаются один раз на весь пакет. Битый или неоткрывающийся файл пропускается
с сообщением об ошибке, остальные обрабатываются дальше. Понимаются расширения mp4, mov,
avi, mkv, webm, m4v, mpg, mts, wmv, flv, 3gp.

Имена файлов кадров:

```
0001_shot01_00-00-00.000_start.jpg
0002_shot01_00-00-02.360_cut_before.jpg
0003_shot02_00-00-02.400_cut_after.jpg
0004_shot02_00-00-05.280_size_change.jpg
0005_shot02_00-00-07.600_count_change.jpg
```

Полезные варианты:

```bash
python cinema_shot.py clip.mp4 -o storyboard --contact-sheet   # своя папка + простыня
python cinema_shot.py clip.mp4 --interval 3                     # плюс кадр каждые 3 с внутри плана
python cinema_shot.py clip.mp4 --cut-threshold 0.25             # ловить более мягкие склейки
python cinema_shot.py clip.mp4 --stable 20                      # реже реагировать на смену крупности
python cinema_shot.py clip.mp4 --detect-every 4                 # быстрее: люди ищутся в каждом 4-м кадре
python cinema_shot.py clip.mp4 --no-persons                     # ещё быстрее: только лица, без YOLOX
python cinema_shot.py clip.mp4 --hero-rel-area 0.5              # строже отсекать массовку
```

Все параметры: `python cinema_shot.py -h`.

## Как это работает

1. **Склейки.** Для каждого кадра считается различие с предыдущим (гистограмма HSV +
   попиксельная разница уменьшенной картинки). Склейка фиксируется, если различие выше
   порога `--cut-threshold` и заметно выше, чем у соседних кадров (`--cut-ratio`), — так
   быстрые панорамы и движение в кадре не принимаются за стык.
2. **Состав героев.** YOLOX находит людей и животных (собак, кошек, лошадей и т. д.) в кадре. Героем считается фигура, которая
   не ниже `--hero-min-height` высоты кадра (по умолчанию 20 %) и по площади не меньше
   `--hero-rel-area` от самой крупной фигуры (по умолчанию 30 %). Остальные — массовка:
   они попадают в столбец «всего», но на раскадровку не влияют. Так прохожие за спиной
   героя на крупном плане не плодят лишних кадров. С `--no-persons` герои считаются по
   лицам по тому же принципу (лицо не меньше 35 % от самого крупного).
3. **Крупность.** По высоте самого большого лица относительно высоты кадра: деталь
   (> 55 %), крупный (> 28 %), средний (> 12 %). Если лицо мельче или его нет (герой
   спиной к камере) — по фигуре героя: фигура видна целиком — общий план; фигура
   обрезана нижним краем кадра и занимает почти всю высоту — средний. Нет ни героев,
   ни лиц — «без героев».
4. **Устойчивость.** Крупность и число людей считаются изменившимися только если новое
   состояние держится в окне из `--stable` кадров (по умолчанию 12 ≈ полсекунды при 25 к/с),
   чтобы одиночные ошибки детектора не плодили лишних кадров.

## Ограничения

* Деление на героев и массовку — эвристика по размеру фигуры. Если герой в общем плане
  такой же мелкий, как прохожие, он попадёт в «массовку»; порог регулируется
  `--hero-min-height` и `--hero-rel-area`.
* Пути с кириллицей и пробелами (например `D:\Видео\Ролик 1.mp4`) поддерживаются: модели и
  кадры читаются и пишутся в обход OpenCV, а видео при необходимости копируется во временную
  папку с латинским именем.
* Скорость: с YOLOX примерно 0,2 с на анализируемый кадр на CPU (15-секундный ролик
  в 720p обрабатывается около 30 с при `--detect-every 2`).
* Плавные переходы (наплывы, затемнения) не выделяются как отдельная склейка; обычно они
  всё равно ловятся как смена крупности/числа героев в новом плане.
* Подписи на `contact_sheet.jpg` латиницей (ограничение шрифтов OpenCV): `CU` — крупный,
  `MS` — средний, `WS` — общий, `ECU` — деталь, `NF` — без героев, `heroes` — число героев,
  `all` — всего людей в кадре.
